# 한국어 보고자료 문법

## 장표 제목

좋은 제목은 긴 문장이 아니라 판단이 보이는 키워드형 메시지다.
특별히 문장형을 요구받지 않았다면 `한다`, `이다`, `필요하다`로 끝내지 않는다.
영어 원문을 직역하지 말고 한국 조직에서 실제로 쓰는 판단/조치/기준 언어로 다시 쓴다.

제목을 쓰기 전에는 독자, 판단, 근거, 다음 행동을 먼저 정한다.

| 항목 | 예 |
|---|---|
| 독자 | 임원, 팀장, 실무자, 개발사 PM |
| 판단 | 적용, 보류, 검증, 승인, 공유 |
| 근거 | 비용, 권한, 일정, 리스크, 산출물 |
| 행동 | 파일럿, 정책 확인, 체크리스트, 개발 반영 |

| 약한 제목 | 좋은 제목 |
|---|---|
| 시장 현황 | 수요 증가 / 구매 전환 특정 채널 집중 |
| 주요 이슈 | 비용 이슈보다 운영 리스크 우선 |
| 추진 방향 | 3개월 PoC / 성과 기준 선검증 |
| Figma 파일이 제작 작업대로 바뀜 | Figma 2026 적용 방향: 산출물 기준 재정의 |
| 바뀌는 건 기능이 아니라 작업 경계 | 파일 역할: 화면 검토에서 산출물 관리로 확대 |
| 접근 가능 기능부터 실험, 닫힌 베타는 대기 | 파일럿 우선순위: 즉시 실험과 보류 항목 분리 |
| 시작 전 잠글 것: 권한·과금·공개 범위 | 확대 적용 전 권한·비용·공개범위 확인 |

## 제목 끝말

권장 끝말:

- 적용 방향
- 검토 기준
- 우선순위
- 전환 기준
- 운영 기준
- 검증 범위
- 선행 확인
- 확대 조건
- 보류 항목
- 전달 포인트

피할 끝말:

- 바뀜
- 잠금
- 대기
- 가능
- 하는 것
- 할 것
- 단독 현황
- 단독 개요
- 단독 이슈

## 기본 장표 패턴

1. 상단: 1줄 결론
2. 중단: 근거 2~3개
3. 하단: 판단/요청/다음 액션

## 한국식 임원보고에 맞는 표현

- “필요합니다”보다 “필요”처럼 짧게 쓴다.
- “검토가 요구됩니다”보다 “검토 필요”처럼 쓴다.
- “관리해야 한다”보다 “관리 포인트”처럼 쓴다.
- “근거를 남긴다”보다 “근거 이력화”처럼 쓴다.
- “우선이다”보다 “우선 적용”처럼 쓴다.
- 수치가 있으면 문장보다 수치를 먼저 배치한다.
- ‘왜 지금 봐야 하는지’를 1장 안에 넣는다.

## 피해야 할 표현

- 혁신적인 솔루션
- 압도적인 효율성
- 데이터 기반 고도화
- 새로운 패러다임
- 미래 경쟁력 확보
- 작업 경계
- 접근 가능 기능
- 적용 전 잠금
- 닫힌 베타 대기
- 기능 채택

이런 표현은 구체적 결과, 수치, 운영 변화로 바꾼다.
